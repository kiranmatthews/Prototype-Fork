# Classic wood crates and orange fruit

Ordinary `wood` crates and five-hit `multihit` crates use an original Meshy oak shipping crate: closed plank panels, a timber frame, real diagonal X braces, painted grain and small iron nails. The original 182 triangles, normals and UVs are preserved. Both the visible model and the existing collider fit the same 0.96 metre cube; the HUD counter reuses the model.

The production GLB is **45,692 bytes**, with one 256 × 256 diffuse texture and one draw per crate. Crates share geometry and Lambert materials. Five-hit crates have a warmer tint that becomes weathered with each hit; their existing squash, five contacts, two fruit per contact, force-smash rules and checkpoint durability remain unchanged. Ghosts and run-mode number/boost faces use the existing cube proxy. A shared, small wooden fallback preserves play if a download fails; late loading cannot attach to a disposed level.

Meshy generation used the official CLI 0.3.1, one 240-triangle-target preview and one texture refinement, costing 15 existing credits. Actual task IDs, hashes and mesh/texture budgets are in `public/props/wood-crate/provenance.json` and `tools/wood-crate-assets/tasks.json`. Authoring responses and full-size downloads stay ignored; credentials never enter the runtime. `prepare_asset.py` reduces only the diffuse image and material metadata, preserving Meshy geometry.

The shared pickups now have a saturated orange body, burnt-orange shading and warm juicy highlights. Their geometry, independent elastic motion, attraction, flight and awards retain the existing contracts. Internal `milk.ts` APIs and the saved `milkMagnetRange` tuning key remain compatible; player-facing labels say fruit and no movement values changed. The fruit HUD is the same orange 3D pickup, with its normal numerical counter. The bottle-filling HUD and blue milk carrier are disconnected, and their 101 PNG frames and two GLBs are removed from the shipped/offline pack (about 4.3 MiB). No cartons are created by the crate factory.

Validation: actual GLB performance/provenance budget, real five-hit player contacts/rewards/checkpoint resets, crate-jump parity, puzzle stack/blast/enemy/finish accounting, shared pickup geometry/motion/depth isolation, and inventory visibility. Lite/full Chrome checks loaded 36 shared wood crates, matching orange HUD art, run-mode restoration, normal 100-fruit life rollover, no milk asset requests and no console errors. Source lab Chrome checks supported spawn, production checkpoint warp/banking, actual pit death and supported respawn, a wood stomp/bounce/reward, and finish-gate traversal. Production type-check and Vite build passed. No full suite was requested or run.

The optional existing `test-game-hud-pipeline.mjs` source audit failed its 2,400-character pause-block regex on the original main source; this task did not change `src/main.ts` or the player movement code. Runtime HUD and visibility checks pass; no unrelated regex adjustment is included.

Browser reports and rendered captures are in `docs/wood-crate-evidence`. Run the browser tools with `PLAYWRIGHT_MODULE` pointing to an installed Playwright module; `browser_review.mjs` also accepts a production or public base URL. `lab_smoke.mjs` uses the local source modules. See `npm run check:fruit-hud` for the focused static asset and HUD-state checks.
